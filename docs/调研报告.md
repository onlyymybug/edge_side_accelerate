# MemoRoute-Agent：面向端侧 Agent 的记忆驱动、离线优先、异构执行统一基础设施

## 1. 核心问题

面向端侧 Agent（本地日程助手、文件/相册/系统控制 Agent、弱网/断网环境下的个人知识助理等），系统同时面临四类约束：

1. **Agent 任务是多阶段的**  
   这些阶段的计算特性不同：长上下文阶段更偏 **prefill-heavy**，逐步生成阶段更偏 **decode-heavy**。
   
2. **很多请求不应该一上来就调用大模型全量推理**  
   很多任务是重复的、低风险的、模板化的，或者可由小模型/规则系统解决。需要一个 **离线优先（offline-first）的分层任务路由器**，先判断是否能直接复用经验或本地轻量处理，再决定是否升级到完整 Agent 运行时。
   
3. **端侧资源受限且异构**  
   手机/边缘 SoC 上同时存在 CPU、GPU、NPU、DRAM 与 UFS/Flash。  
   不同执行阶段的瓶颈不同：prefill 更偏算力，decoding 更偏内存带宽；稀疏执行、I/O、GPU-NPU 同步都可能成为瓶颈。

4. **经验记忆不能只服务回答内容，还应服务系统决策**  
   端侧 Agent 的经验记忆不仅要帮助模型“记住用户”，还应帮助系统判断：
   - 是否可直接复用历史成功轨迹
   - 是否需要调用完整大模型
   - 下一个 phase 大概率是什么
   - 哪些上下文块、参数块、图执行计划值得提前预热

## 2. 现有工作的做法

### 2.1 PowerInfer：PC 端稀疏激活推理与 GPU-CPU 协同

**主要做法**：
- 观察到神经元激活呈幂律分布，存在少量 **hot neurons** 和大量 **cold neurons**
- 将 hot neurons 预放到 GPU，cold neurons 留在 CPU
- 使用在线 predictor 预测当前会激活哪些神经元
- 设计 neuron-aware sparse operator 和离线 solver 决定放置策略

### 2.2 PowerInfer-2：手机端 NPU/CPU 协同与 I/O 感知执行

**主要做法**：

- 提出 **neuron cluster** 作为手机端推理的执行基本单位
- prefill 阶段采用 **NPU-centric** dense 执行
- decoding 阶段采用 **CPU-NPU hybrid** 稀疏执行
- 设计 neuron cache、flexible loading、cluster-level pipeline 来隐藏 UFS I/O

### 2.3 EdgeMoE：MoE 模型的 expert 外存管理

**主要做法**：
- 针对 MoE 模型，观察到 expert 权重大、占内存，但每次只激活少数 expert
- 将 non-expert 权重常驻内存，将 expert 作为“冷数据”放在外存
- 设计 **expert-wise bitwidth adaptation**
- 设计基于 activation path 的 **expert preload**
- 设计面向 expert buffer 的 **cache eviction policy**

### 2.4 HeteroInfer：手机 SoC 上 GPU-NPU 的异构执行与同步优化

**主要做法**：

- 提出 **layer-level + tensor-level GPU-NPU parallelism**
- 提出 **weight-centric / activation-centric / hybrid** 三种 partition
- 设计基于 UMA 的 **fast synchronization**
- 建立 **profiler + solver + inference engine** 的完整框架

## 3. 设计的核心技术

### 技术一：Memory-Guided Hierarchical Task Routing

#### 核心思想
让经验记忆直接参与任务路由，而不是只参与 prompt augmentation。

- **Level 0：Direct Memory Replay**  
  高相似、低风险任务直接复用历史成功模板
- **Level 1：Lightweight Local Executor**  
  用规则 / 小模型 / FSM 处理简单任务
- **Level 2：Small-LLM Planner**  
  用小模型完成工具选择、参数草拟、检索查询改写
- **Level 3：Full Agent Runtime**  
  复杂任务才进入完整大模型 Agent 流程

#### 创新点
记忆不再只是“生成时的附加上下文”，而是直接控制：
- 是否需要调用大模型
- 是否需要进入完整 Agent 规划
- 是否可复用成功轨迹

---

### 技术二：Phase-Conditioned Predict-then-Prepare Runtime

#### 核心思想
将一次 Agent 交互拆成多个 phase，并预测下一 phase，从而提前准备执行资源。

#### 划分的 phase 如：
1. **Intent / Plan phase**：长 prompt、长工具说明，prefill-heavy  
2. **Memory fusion / Retrieve phase**：插入记忆块、tool schema、历史摘要，仍偏长上下文  
3. **Action generation phase**：生成 tool call / 参数，decode-heavy  
4. **Tool-return resume phase**：工具结果回来后恢复上下文，shape 突变明显  
5. **Branch / Reflection phase**：Best-of-N、自一致性、多候选动作、失败重规划

#### 创新点
不是只预测下一层 expert 或同步等待时间，而是预测 **agent 层的 phase 转移**，把任务逻辑预测与底层资源准备统一起来。

---

### 技术三：Hierarchical State & Parameter Cache

#### 核心思想
统一管理三类缓存对象：

1. **Parameter Cache**
   
2. **Agent State Cache**
   
3. **Execution Artifact Cache**

#### 统一优先级打分
```text
score = α * reuse + β * next_phase_prob + γ * reload_cost + δ * latency_criticality
```

其中：
- `reuse`：历史复用率
- `next_phase_prob`：由 phase predictor 给出
- `reload_cost`：从 UFS / graph rebuild / retrieval rebuild 的代价
- `latency_criticality`：对 TTFT / TPOT 的影响程度

#### 创新点
现有工作多数只缓存模型参数；这里进一步把 **Agent 状态块** 和 **执行工件** 统一纳入缓存体系，形成面向 Agent OS / runtime 的统一资源管理层。

## 5. 底层运行时设计

### 5.1 端侧异构执行调度
借鉴 HeteroInfer：
- prefill：**NPU 主导，GPU 辅助**
- decoding：**GPU 主导，NPU 辅助**，重点是吃满 SoC 带宽

### 5.2 稀疏 / I/O 感知执行
借鉴 PowerInfer-2：
- neuron cluster hot/cold 管理
- 根据 batch / branch 数动态调整 hot/cold region

## 6. 评测数据集与任务设计

### 6.1 基础 LLM 任务集
用于验证 prefill / decode 的底层性能：
- **BELLE_multiturn_chat**
- **GSM8K**
- **LongBench / TriviaQA**

### 6.2 手机端真实工作负载
用于验证不同类型 agent workload 的一致性：
- role-play
- multi-turn dialog
- math
- coding

### 6.3 MoE / 总结类任务
用于测试 expert cache / preload / mixed precision：
- **XSum**
- **SAMSum**
- **Wikipedia-jp**

## 7. 评测指标

### 基础推理指标
- TTFT（Time To First Token）
- TPOT（Time Per Output Token）
- prefill throughput

### Agent 任务级指标
- task completion latency
- offline completion ratio

### 资源指标
- cache hit rate（parameter / state / graph）
- energy per task

### 用户体验与干扰
- 与游戏 / 视频 / 相机并发时的 FPS 与时延变化
- foreground interference 下的 Agent latency 抖动
