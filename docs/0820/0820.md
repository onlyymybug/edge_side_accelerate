# 0820：OnePlus Llama3.1-8B 与 Qwen2.5-3B 对 Finding 1/2 的初步证据

## 1. 范围与结论摘要

本文整理以下四组实验，并在同一台 OnePlus 上按相同任务对比 Llama3.1-8B 与 Qwen2.5-3B：

- OnePlus × Llama3.1-8B × MATH500 × Balanced × no-budget
- OnePlus × Qwen2.5-3B × MATH500 × Balanced × no-budget
- OnePlus × Llama3.1-8B × GSM8K × Balanced × no-budget
- OnePlus × Qwen2.5-3B × GSM8K × Balanced × no-budget

四组实验的设备硬件序列号均为 `3B15B800A0R00000`，设备型号为 PLQ110、SoC 为 SM8750；均使用 QNN 2.37、HTP performance mode 8（Balanced runtime override）、greedy decoding、shared buffer 和 `max_seq_len=1024`。`no-budget` 表示不设置独立的 output-token cap，输出仍受总序列长度 1024 限制。当前没有 BitNet 在同设备、相同任务、Balanced/no-budget 下的结果，因此模型对照只包含 Llama 与 Qwen。

本文按 `pace_task.pdf` 的 Finding 1 和 Finding 2 组织证据。核心结论如下：

1. **Finding 1 当前得到负面结果，而不是排名反转。**tokens/s、J/token、EDP 在 2 个任务 × 4 个 deadline 的 8 个条件中都选择 Qwen；energy per correct task under deadline 也都选择 Qwen。三种 proxy 的 winner disagreement rate 均为 0%，Kendall's tau 均为 +1，task-oracle regret 均为 0%。其中 MATH500 的 4 个条件因各缺一条运行记录，只能视为 provisional；只保留完整 GSM8K 后结论仍为 0% disagreement、tau=+1。
2. **Finding 2 获得部分支持。**不存在一个同时满足所有任务与 correctness target 的固定模型：MATH500 上 Qwen 的准确率和能效都更好；GSM8K 在准确率目标不高于 62.09% 时 Qwen 能耗最低，但目标处于 62.09%–72.63% 时只有 Llama 能满足。GSM8K 的及时成功优势还会从 20 秒时的 Qwen 移到 30 秒高正确率目标下的 Llama。
3. **当前不能完整验证 Finding 2。**四组主实验都使用 Balanced/no-budget，因此 reasoning budget 和 runtime configuration 没有形成对齐的跨模型 sweep；difficulty 维度上 Qwen 在 MATH500 Level 1–5 全部保持最低 energy/correct，没有发生 operating-point 移动。这些都必须作为负面结果或证据缺口报告。
4. **Qwen 的系统性能和能效在两个任务上都明显更好。**其 decode 吞吐约为 Llama 的 1.94 倍，TTFT 低 24%–31%，平均端到端延迟低约 40%，J/token 低 56%–57%，平均 EDP 低约 75%。
5. MATH500 两组各有一条 telemetry 前置命令超时，并非模型推理崩溃。因此准确率可以按 499 条已评分样本报告，但 deadline 能效目前只能作为 provisional 结果。

## 2. 统计口径

- 正确率：读取 `summary.csv` 中当前 `math_benchmarks_v2_relaxed_prm800k` 评分结果。GSM8K 使用宽松答案提取与数值等价；MATH500 使用宽松答案提取与 PRM800K/SymPy 数学等价判分，不要求固定答案格式。
- TTFT：成功样本 `ttft_ms` 的算术平均，越低越好。
- tokens/s：成功样本 `decode_token_per_sec` 的算术平均，越高越好。
- 端到端延迟：成功样本 `e2e_latency_ms` 的算术平均。
- J/token：有效实测总能量除以对应的总生成 token 数，越低越好。
- EDP：逐样本 `energy_j × inference_ms / 1000` 后取算术平均，单位 J·s，越低越好。
- 总能量/正确题：整批有效实测总能量除以正确题数。该值用于描述整批实验为获得一个正确结果付出的平均能量，不带 deadline 条件。
- energy per correct task under deadline：整批实测总能量除以在指定 `inference_ms` deadline 内答对的题数。它不是“及时答对样本自身能量”的平均值。
- winner disagreement rate：在给定 `task × deadline` 条件集合中，proxy 选出的第一名与 task oracle 第一名不同的条件比例。
- Kendall's tau：proxy 排名与 energy per correct task under deadline 排名之间的 Kendall 等级相关。本报告每个条件只有两个配置，因此 tau 只能取 +1 或 -1；它只能判断是否反转，不能描述更细的排序结构。
- task-oracle regret：`(proxy winner 的 task metric - 该条件最优 task metric) / 该条件最优 task metric`。越低越好；proxy 与 oracle 选择相同时为 0%。
- task-sufficient operating point：在满足指定 correctness 或 timely-success target 的配置中，选择整批实测能量最低的配置。若没有配置满足目标，则记为不可达，而不是强行选择相对最好者。
- 表内 `#1/#2` 只表示同一任务中两模型的排名。准确率和 tokens/s 降序；TTFT、延迟、J/token、EDP 升序。

能耗来自整机电池侧采样，包含手机其他组件和 telemetry 开销，并非隔离的 NPU 能耗。虽然四组使用同一设备，但运行日期、电池状态、温度和后台负载并非严格锁定，因此能耗差异可作为强趋势，不能等同于实验室条件下单变量、随机交错运行的纯模型因果效应。

## 3. Finding 1：Token-level proxy 是否选错任务级最优配置

### 3.1 配置与 proxy 排名

记 Qwen2.5-3B 为 Q、Llama3.1-8B 为 L。两个任务的三种 proxy 排名完全相同：

| 任务 | tokens/s 排名 | J/token 排名 | EDP 排名 |
| --- | --- | --- | --- |
| MATH500 | Q #1（14.892），L #2（7.655） | Q #1（0.02526），L #2（0.05767） | Q #1（555.10），L #2（2274.18） |
| GSM8K | Q #1（14.925），L #2（7.709） | Q #1（0.02498），L #2（0.05868） | Q #1（66.41），L #2（259.37） |

三种 proxy 都会选择 Qwen。这里比较的是两个 **runtime-native deployment**：模型 family、规模和量化并不相同，因此结果只能解释为完整部署方案排名，不能把差异全部归因于 QNN runtime。

### 3.2 Task-oracle 排名

Task oracle 使用 energy per correct task under deadline，数值越低越好。若某配置在 deadline 内没有正确题，则其 task metric 视为 `+∞`；这样可以参与可行性排名，但不报告有限的 J/correct 数值。

| 任务 | Deadline | Qwen | Llama | Task-oracle winner |
| --- | ---: | ---: | ---: | --- |
| MATH500† | 5 s | 6550.64 J / 1 | +∞ / 0 | Qwen |
| MATH500† | 10 s | 1310.13 J / 5 | 2205.30 J / 6 | Qwen |
| MATH500† | 20 s | 81.88 J / 80 | 264.64 J / 50 | Qwen |
| MATH500† | 30 s | 40.19 J / 163 | 150.36 J / 88 | Qwen |
| GSM8K | 5 s | 229.58 J / 25 | 11547.84 J / 1 | Qwen |
| GSM8K | 10 s | 14.00 J / 410 | 135.86 J / 85 | Qwen |
| GSM8K | 20 s | 7.22 J / 795 | 16.26 J / 710 | Qwen |
| GSM8K | 30 s | 7.03 J / 817 | 12.47 J / 926 | Qwen |

`†` MATH500 两组都只有 499/500 完成，四行均为 provisional；GSM8K 四行是完整 1319/1319 结果。

### 3.3 Winner disagreement、Kendall's tau 与 regret

| Proxy policy | 纳入的 task × deadline 条件 | 与 task oracle 不同 | Winner disagreement rate | 平均 Kendall's tau | 平均 task-oracle regret |
| --- | ---: | ---: | ---: | ---: | ---: |
| maximum tokens/s | 8 | 0 | 0/8 = 0% | +1.000 | 0.00% |
| minimum J/token | 8 | 0 | 0/8 = 0% | +1.000 | 0.00% |
| minimum EDP | 8 | 0 | 0/8 = 0% | +1.000 | 0.00% |

保守地排除 provisional MATH500，只使用完整 GSM8K 的 4 个 deadline，三种 proxy 仍都是 disagreement 0/4、tau=+1、regret=0%。

### 3.4 排名反转与负面结果

当前矩阵中**没有发生 Finding 1 所假设的 proxy/task 排名反转**。Qwen 在 tokens/s、J/token 和 EDP 上都排名第一，也在每个 deadline 上获得最低 energy per correct task。因而当前证据不能支持“token-level proxy 会选错任务级最优配置”，反而构成一个必须报告的排名一致负面结果。

这不意味着 Finding 1 已被否定。当前统计只有两个跨模型 deployment，且 Qwen 在三个系统 proxy 上同时占优，排序难度过低；Kendall's tau 对两个配置也只能是 ±1。后续至少需要加入同模型不同 HTP mode、不同 budget 和不同 runtime 的三个以上配置，并对关键点做独立能耗重复，才可能稳定估计 disagreement、tau 和 regret。

准确率排名本身确实发生跨任务反转：MATH500 是 Qwen 第一，GSM8K 是 Llama 第一。但这不是 Finding 1 定义的“proxy 与 energy/correct 排名反转”，而是 Finding 2 中 task/correctness target 改变 sufficient boundary 的证据。

## 4. Finding 2：是否存在固定的 task-sufficient operating point

### 4.1 证据覆盖

| Finding 2 要求维度 | 当前覆盖 | 当前能支持的判断 |
| --- | --- | --- |
| deadline | 5/10/20/30 s | GSM8K 完整；MATH500 provisional。及时成功边界随 deadline 移动 |
| difficulty | MATH500 Level 1–5 | Qwen 五级均占优；成本随难度上升，但配置 winner 未移动 |
| reasoning budget | 主对照只有 no-budget | 不能检验跨模型 budget boundary |
| model size/family | Qwen2.5-3B 与 Llama3.1-8B | 可以做 deployment-level 对比，不能归因为单纯模型规模或 runtime |
| correctness target | 可由实测准确率构造分段 target | GSM8K target 超过 62.09% 后 operating point 从 Qwen 移到 Llama |
| runtime configuration | 两模型均为 QNN Balanced | 不能检验 Burst/Balanced/LowPower 或跨 runtime boundary |

因此，本报告只能称为 Finding 2 的**第一版、部分证据**，不能声称已经形成完整的 `task × difficulty × deadline × budget × model` sufficient operating boundary。

### 4.2 Task、model family 与 correctness target

以“满足总体准确率目标的配置中整批能量最低”为 sufficient operating point，可得到以下分段边界：

| 任务与 correctness target | 可行配置 | 最低能耗 sufficient point |
| --- | --- | --- |
| MATH500 target ≤ 34.87% | Qwen、Llama | Qwen |
| MATH500 34.87% < target ≤ 46.69% | 仅 Qwen | Qwen |
| MATH500 target > 46.69% | 无 | 不可达 |
| GSM8K target ≤ 62.09% | Qwen、Llama | Qwen |
| GSM8K 62.09% < target ≤ 72.63% | 仅 Llama | Llama |
| GSM8K target > 72.63% | 无 | 不可达 |

这张表给出当前最直接的 Finding 2 证据：不存在跨任务、跨 correctness target 的固定模型选择。Qwen 是 MATH500 所有可达 target 的 sufficient point；GSM8K 在较低 target 下选择 Qwen，但 target 一旦超过 Qwen 的能力上限，就必须移动到能耗更高、速度更慢的 Llama。

准确率的 Wilson 95% 置信区间为：MATH500 Llama 30.82%–39.15%、Qwen 42.36%–51.08%；GSM8K Llama 70.16%–74.97%、Qwen 59.44%–64.67%。两个任务中两模型区间均不重叠，当前准确率排序不是由简单抽样波动造成的。

### 4.3 Deadline × timely-success target

GSM8K 的完整数据最清楚地显示 deadline boundary：

| Deadline | Llama timely success | Qwen timely success | Boundary 解释 |
| ---: | ---: | ---: | --- |
| 5 s | 1/1319，0.08% | 25/1319，1.90% | Qwen 更可行且能耗更低 |
| 10 s | 85/1319，6.44% | 410/1319，31.08% | Qwen 明显占优 |
| 20 s | 710/1319，53.83% | 795/1319，60.27% | target ≤53.83% 时二者可行但 Qwen 能耗低；53.83%–60.27% 仅 Qwen 可行 |
| 30 s | 926/1319，70.20% | 817/1319，61.94% | target ≤61.94% 时 Qwen 能耗低；61.94%–70.20% 仅 Llama 可行 |

例如 timely-success target=60% 时，20 秒只能选择 Qwen；target=65% 时 20 秒无配置可达，放宽到 30 秒后只能选择 Llama。也就是说，deadline 与 correctness target 的联合变化会使 sufficient operating point 从 Qwen 移到 Llama，而不是存在固定全局 winner。

MATH500 的及时正确率在 5/10/20/30 秒下分别为：Llama 0%、1.20%、10.00%、17.60%；Qwen 0.20%、1.00%、16.00%、32.60%。10 秒时 Llama 多一个及时正确结果，但 Qwen 的 energy/correct 更低；20 秒和 30 秒时 Qwen 在及时正确数和能效上都占优。由于各缺一条样本，这一部分只作为 provisional observation。

### 4.4 Difficulty boundary 与排名一致负面结果

| MATH500 难度 | Llama energy/correct | Qwen energy/correct | 最低能耗配置 |
| ---: | ---: | ---: | --- |
| Level 1 | 18.96 J | 9.05 J | Qwen |
| Level 2 | 40.80 J | 14.95 J | Qwen |
| Level 3 | 57.06 J | 23.05 J | Qwen |
| Level 4 | 102.36 J | 35.76 J | Qwen |
| Level 5 | 287.72 J | 84.66 J | Qwen |

难度显著抬升了完成正确任务的成本：Llama 从 Level 1 的 18.96 J/correct 增至 Level 5 的 287.72 J/correct，Qwen 从 9.05 增至 84.66 J/correct。但在当前两个配置之间，difficulty 没有改变 winner，五个等级都由 Qwen 占优。这是 Finding 2 在 difficulty 维度上的排名一致负面结果，而不是 boundary shift。

### 4.5 Budget 与 runtime configuration：当前不能支持的结论

本报告的四组主结果全部是 Balanced/no-budget。虽然本地另有部分 Qwen budget-256/512 和其他 mode 的实验，但不存在与 Llama 对齐且全部采用当前评分、完整覆盖的 `model × budget × mode` 矩阵；Llama MATH500 Balanced/budget-512 当前也只有 2/500 条，不能纳入正式比较。因此当前不能回答：

- Llama 与 Qwen 的 sufficient point 是否随 reasoning budget 一致移动；
- 同一模型在 Burst、Balanced、LowPower 下是否发生 task-level winner reversal；
- budget 与 deadline 的交互是否会改变 task-oracle winner；
- 当前模型差异中有多少来自规模、family、量化或 runtime。

补齐 Finding 2 至少需要：两模型在 budget-256、budget-512、no-budget × Burst、Balanced、LowPower 下运行相同完整数据集，统一使用当前 scorer，并在每个关键 operating point 完成至少 5 个独立能耗批次。之后才能形成任务书要求的 `task × difficulty × deadline × budget × model` sufficient operating boundary。

### 5.3 逐题正确性重叠

两模型共有 498 道题同时存在有效评分；另外两道分别是不同模型的运行失败样本。

| 两者都正确 | 133 | 26.71% |
| 仅 Llama 正确 | 41 | 8.23% |

Qwen 独占正确题数是 Llama 的 2.41 倍，这与其总体准确率优势一致。两者都错误的题目仍有 225 道，说明即使组合两模型也不能覆盖近一半的共同有效样本。

在 20 秒和 30 秒 deadline 下，Qwen 同时获得更多及时正确题和更低的 energy per correct；10 秒下 Llama 多一个及时正确结果，但 Qwen 因整批总能量更低，单位及时正确题能量仍更低。

### 5.5 数据完整性

- Llama 失败样本：`math500_0418`。
- Qwen 失败样本：`math500_0474`。
- 两条错误均为主机通过 ADB 执行 `dumpsys battery` 时超过 15 秒，不是 runner 或模型推理崩溃。
- 两组所有成功样本均可提取答案并完成评分。

补跑这两条后，准确率最多变化约 0.2 个百分点，但补齐是生成正式 full-dataset deadline 指标的必要条件。

| 平均峰值内存 | 1474 MB | 1003 MB | Qwen 少约 471 MB |

GSM8K 呈现明确的能力—效率交换：Llama 的准确率高 10.54 个百分点，但 Qwen 的吞吐接近两倍，平均端到端延迟和单题能量约为 Llama 的 60% 和 50%。Qwen 平均输出还比 Llama 长 16.8%，因此其性能和能效优势同样不是由更短回答造成。

虽然 Qwen 正确题更少，但其整批总能量从 Llama 的 11547.84 J 降至 5739.59 J，降幅超过正确数降幅，所以“总能量/正确题”仍从 12.05 J 降至 7.01 J。若系统目标是单位能耗获得尽可能多的正确结果，Qwen 更优；若不设置严格延迟或能量约束、只追求最终准确题数，则 Llama 更优。

## 7. 模型选择建议

| 使用目标 | 建议模型 | 原因 |
| --- | --- | --- |
| MATH500 综合效果 | Qwen2.5-3B | 准确率高 11.82 pp，且速度、能效、内存均明显更优 |
| GSM8K 最高准确率 | Llama3.1-8B | 多答对 139 题，准确率高 10.54 pp |
| GSM8K 严格 deadline | Qwen2.5-3B | 20 秒以内及时正确数更多，且 energy per correct 更低 |
| 最低 J/token 或 EDP | Qwen2.5-3B | 两任务均显著领先 |
| 较低内存占用 | Qwen2.5-3B | 平均峰值内存约少 471 MB |

总的来说，Qwen2.5-3B 是更均衡的端侧部署选择：它在 MATH500 同时获得更高质量和更低系统成本，在 GSM8K 则以约 10.5 个百分点的准确率代价换取接近两倍吞吐和明显更好的能效。Llama3.1-8B 的主要价值集中在 GSM8K 的最终准确率，而不是端侧性能或能效。
