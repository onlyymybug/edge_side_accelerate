# GUI Agent 推理服务占用与空闲时间研究

2026-11-06，在现有真机原型上完成一次连续测量。核心结果：**任务循环内，模型计算占 44.89%，没有模型计算占 55.11%；服务 ready 到 shutdown 的无请求处理占比为 57.52%。**

架构为主机编排、手机运行 Qwen3-VL-4B/GenieX/QAIRT 与 Markor，主机通过 USB/ADB 获取界面并提交请求。模型常驻，只加载一次；每个请求重置 KV。当前代理每步一次动作推理，没有 M3A 的第二次反思调用。

## 测量样本和时间窗口

两种任务（新建文件夹、新建笔记）各重复三次，最多 12 步，共 6 次试跑、67 次推理调用。2 次笔记任务成功，4 次到步数上限未成功；所有步骤、失败、无效动作和重试均计入。

| 口径 | 窗口秒数 | 模型/请求繁忙秒数 | 空闲秒数 | 空闲率 |
|---|---:|---:|---:|---:|
| 任务循环，计算口径 | 510.386 | 229.119 | 281.267 | 55.11% |
| 任务循环，主机在途请求口径，含 IPC | 510.386 | 229.490 | 280.896 | 55.04% |
| 常驻服务 ready → shutdown，原生请求处理口径 | 539.437 | 229.144 | 310.294 | 57.52% |

第三行还包括任务间启动应用、初始化、最终截图等空档；前两行不包括这些阶段。首次模型加载 **5.485 秒**、退出释放约 **0.370 秒**另列，均不作为已 ready 的空闲。

成功试跑单独统计的未计算比例为 **54.26%**，失败试跑为 **55.46%**；本次结果没有通过剔除失败步骤来抬高或降低空闲率，但两种任务和少量成功样本仍不足以代表整个 benchmark。

## 时间分解

| 互斥阶段 | 总秒数 | 任务循环占比 |
|---|---:|---:|
| 模型请求，含请求/响应 IPC | 229.490 | 44.96% |
| 界面采集：UI 树、截图、解析及采集前等待 | 211.554 | 41.45% |
| 动作执行及动作后等待 | 37.080 | 7.27% |
| 每步 AndroidWorld 成功校验 | 14.855 | 2.91% |
| 请求文件上传 | 9.599 | 1.88% |
| 本地图片、提示词准备 | 7.541 | 1.48% |
| 解析、反馈、日志和其余间隙 | 0.266 | 0.05% |

模型计算时间 229.119 秒内：视觉编码 **7.018 秒**、prefill **66.566 秒**、decode **149.104 秒**，其余 reset/template/SDK 内部及计时边界开销约 **6.431 秒**。TTFT 与上述阶段存在重叠，未重复相加。

非推理时间主要集中在以下几处：

- UIAutomator 获取 UI 树 **144.910 秒**，平均 **2.163 秒/步**。包含命令启动、ADB 和获取稳定 UI 的等待，不能全部解释为应用本身执行慢。
- 显式固定等待合计 **59.146 秒**：采集前 0.5 秒，未报错的动作后 0.4 秒，status 声明也会经历后者。
- 真正的动作执行器时间，扣除明确等待后，仅 **11.456 秒**，占循环约 **2.24%**。点击平均约 **0.113 秒**；input_text 约 **0.413 秒**，后者平均值包含两次被拒绝的输入目标。

仅在算术上扣除上述固定等待，其他时间保持不变，未计算比例仍为 **49.22%**。这不是移除等待后的实际实验，UI 稳定等待可能转移到其他阶段。

## 空档长度与含义

同一任务内，61 个相邻请求空档：

| 指标 | 秒数 |
|---|---:|
| 最小 | 3.406 |
| P05 | 3.953 |
| 中位数 | 4.157 |
| P95 | 4.580 |
| 最大 | 4.829 |

这些是设备原生时钟记录的“上个请求处理完毕 → 下个请求收到”时间。未把首次请求前、跨任务和退出前的长空档混入上表。

这说明当前原型存在反复出现、持续约 4 秒的无请求窗口，值得做后台计算填充实验。**它不表示 NPU 硬件有 55% 空闲，也不证明另一个模型能无损使用这 55% 时间。** 权重仍占内存，GUI 和采集占用 CPU 等资源，尚未测量其他 NPU 用户、功耗或竞争。若尝试利用空档，应另测前台优先、后台任务可中止以及前台 P95 延迟是否恶化。

在动作序列与其他时间不变的条件下，由分解数字推导：仅将模型计算加速两倍，循环约加速 **1.29 倍**；仅加速模型的理论上限约 **1.81 倍**。这支持同时研究环境采集开销，而不能只优化推理。

## 不能外推的范围

本次测的是当前自定义代理和 UIAutomator/ADB 原型，不是通用 GUI Agent 固有空闲率。[上游 M3A](https://github.com/google-research/android_world/blob/55ddaf5edc6f6c25673aed343907d5b9dca66f84/android_world/agents/m3a.py) 在常规动作后默认等 2 秒、再次采集界面，还会调用模型生成摘要；其计算与空闲结构会不同。原生 Accessibility/截图接口取代 CLI 采集后，空闲率也需重新测量。

动作时间计到输入命令返回；未用帧时间线精确定位应用渲染完成。空闲率只针对这两种任务、当前图像尺寸、提示词、KV 重置策略和代理调用次数。下一轮应固定成功轨迹/动作类型、增加其他应用任务，并把单次动作推理与动作+反思两种代理分别统计。
